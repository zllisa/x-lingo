# 语法书导入操作手册

把一本纸质/PDF 韩语语法书变成 App「学习库 → 语法 → 语法书」里可浏览、可收藏、可搜索的条目。
**核心思路**：图片→文字用本地工具（零模型 token），文字→结构化 JSON 才用模型（可分批、可控成本）。

相关文件：
- 数据：[`constants/grammarBook.ts`](../constants/grammarBook.ts)（`GrammarEntry[]`）
- 类型：[`types/index.ts`](../types/index.ts)（`GrammarEntry` / `GrammarTable` / `GrammarSense` / `GrammarExample`）
- UI：[`app/(tabs)/library.tsx`](../app/(tabs)/library.tsx)（分组列表 + 详情弹窗 + 高亮 + 表格 + 句型分条）

---

## 前置准备（一次性）

```bash

python3 -m pip install --quiet pymupdf pyobjc-framework-Vision pyobjc-framework-Quartz
```

> 说明：本机的 macOS Vision「精准模式」只支持英文，中韩文必须用「快速模式」
> （`setRecognitionLevel_(0)`）。`ocrmac` 封装包会因按精准模式校验语言而报错，所以下面直接调底层 Vision。

## ① 探测：是文字版还是扫描图？（几乎零成本）

```bash
f="/path/to/新书.pdf"
for m in "/Font" "/Image" "/DCTDecode" "ToUnicode" "/Type0"; do
  printf "%-12s %s\n" "$m" "$(LC_ALL=C grep -a -o "$m" "$f" | wc -l | tr -d ' ')"
done
```

- `/Font`、`ToUnicode`、`/Type0` **有值** → 文字版：`pdftotext "$f" out.txt` 直接抽，跳到 ③。
- 全是 0，且 `/Image`、`/DCTDecode` 很多 → **扫描图版**，走 ②。

## ② 两遍 OCR（本地，零 token）

**为什么两遍**：Vision 只认列表里第一个语言，同一行的第二语言会被搞烂。
本书例句是「韩文 / 中文」同行混排，所以跑两遍：一遍韩文优先取干净韩文，一遍中文优先取干净中文，按行 y 坐标对齐。

把下面存成 `batch_ocr.py`，改好 `PDF` 路径后 `python3 batch_ocr.py`：

```python
import fitz, Vision, Quartz, time
from Foundation import NSURL
PDF = "/path/to/新书.pdf"          # ← 改这里
OUT = "grammar_ocr.txt"
doc = fitz.open(PDF); N = doc.page_count

def ocr(cg, langs):
    req = Vision.VNRecognizeTextRequest.alloc().init()
    req.setRecognitionLevel_(0)                 # 0 = fast（支持中韩）
    req.setRecognitionLanguages_(langs)
    req.setUsesLanguageCorrection_(True)
    h = Vision.VNImageRequestHandler.alloc().initWithCGImage_options_(cg, None)
    h.performRequests_error_([req], None)
    res = []
    for o in (req.results() or []):
        c = o.topCandidates_(1)
        if c:
            bb = o.boundingBox()
            res.append({"t": c[0].string(), "y": round(1 - bb.origin.y, 4), "x": round(bb.origin.x, 4)})
    return sorted(res, key=lambda r: (r["y"], r["x"]))

def cluster(ko, zh, tol=0.012):
    items = sorted([("KO", r) for r in ko] + [("ZH", r) for r in zh], key=lambda p: p[1]["y"])
    rows, cur, cy = [], [], None
    for tag, r in items:
        if cy is None or abs(r["y"] - cy) <= tol:
            cur.append((tag, r)); cy = r["y"] if cy is None else (cy + r["y"]) / 2
        else:
            rows.append(cur); cur = [(tag, r)]; cy = r["y"]
    if cur: rows.append(cur)
    out = []
    for row in rows:
        k = " ".join(r["t"] for tg, r in sorted(row, key=lambda p: p[1]["x"]) if tg == "KO").strip()
        z = " ".join(r["t"] for tg, r in sorted(row, key=lambda p: p[1]["x"]) if tg == "ZH").strip()
        out.append((k, z))
    return out

t0 = time.time()
with open(OUT, "w") as fout:
    for p in range(N):
        pix = doc[p].get_pixmap(dpi=330); pix.save("_pg.png")
        src = Quartz.CGImageSourceCreateWithURL(NSURL.fileURLWithPath_("_pg.png"), None)
        cg = Quartz.CGImageSourceCreateImageAtIndex(src, 0, None)
        ko = ocr(cg, ["ko-KR", "zh-Hans"])   # 韩文优先
        zh = ocr(cg, ["zh-Hans", "ko-KR"])   # 中文优先
        fout.write(f"\n{'='*60}\n=== 第 {p+1} 页 (index {p}) ===\n{'='*60}\n")
        for k, z in cluster(ko, zh):
            if k or z: fout.write(f"[KO] {k}\n[ZH] {z}\n")
        fout.flush()
        if p % 10 == 0: print(f"{p+1}/{N}  {time.time()-t0:.0f}s", flush=True)
print("DONE ->", OUT)
```

产物 `grammar_ocr.txt`：每行 `[KO]`（韩文优先遍）/`[ZH]`（中文优先遍）已按行对齐。
**质量预期**：韩文例句、中文说明/翻译近乎完美；缺陷 = 约一半例句的**中文翻译**读不到（下一步补）、`(36回真题)` 常被认成 `36미분`、注意句里内嵌的韩文助词会乱。

## ③ 结构化：文字 → `GrammarEntry[]`（模型，按 Unit 分批）

**这一步才花 token，务必按 Unit 一个个做，做完一批验一批。**

数据结构（见 `types/index.ts`）：

```ts
GrammarEntry {
  id: string            // 'g' + 编号，如 'g19'
  no: number            // 书中编号
  title: string         // 语法点。助词/词尾 → 韩文形式(에서/-ㅂ니다)；
                        //         概念/分类条目 → 书上的中文标题(陈述句间接引用1)
  pattern?: string      // 句型/接续公式（如"动词基本形：动词词干 + 다"）。多条用「；」或「 / 」分隔，UI 自动拆行
  explanation: string   // 说明。**可为空 ''**：概念单元用「说明1/2」大节标题时，正文放进 table，卡片描述会自动兜底取首个 table.text
  senses?: {label,text}[]   // 说明1/2/3 多义项（渲染在"说明"区，标签+正文）
  tables?: GrammarTable[]   // 见下方 GrammarTable（不止对照表，也承载分组/例词/例文/说明段落）
  examples: {ko,zh,zhSrc,exam?}[]    // 条目级例句（白卡片，带"例文"标签）；zhSrc:'ocr'=原书 | 'ai'=AI补译；exam:"36回"
  note?: {text, examples?}           // 注意（text 会按 ①②③ 自动分条展示）
  unit: string          // "Unit 5 格助词"
  book: string          // 书名（同一本用同一个常量）
}

GrammarTable {                       // 一个"块"：可以是对照表 / 例词组 / 例文组 / 说明段落
  title?: string        // 块标题
  level?: 'section'|'item'  // 标题层级：section=大节(说明1/2，最大加粗) | item=小项(① ②，小一号) | 省略=普通表标题
  text?: string         // 标题下的普通说明段落（区别于橙色"注意"框），用于夹在中间的"说明2"定义
  headers?: string[]    // 表头（省略=无网格）
  rows?: string[][]     // 每行单元格（**可省略** → 纯"标题+例句"分组，无网格）
  merges?: {col,row,span}[]  // 纵向合并单元格：col 列从 row 行起合并 span 行；被合并行该格留 ''，值放首行
  note?: string         // 本表下方的"注意"（同样按 ①②③ 自动分条）
  examples?: {ko,zh,zhSrc,exam?}[]  // 本表下方的例句（内联紧凑：韩文+译文同行）。用于把表里的"例词/例文"抽出来平铺
}
```

**结构化规则**：
1. 韩文（title / 例句 / pattern 里的韩文）→ 取 `[KO]` 遍，可靠。
2. 中文说明/注意 → 取 `[ZH]` 遍，可靠。
3. 例句中文翻译 → `[ZH]` 有就用（`zhSrc:'ocr'`）；**没有就按韩文自己翻译**（`zhSrc:'ai'`）。AI 补译只保证意思对，用词未必和原书一致——用户校对时只重点看 `ai` 的。
4. `(XX回真题)` → 抽成 `exam:"XX回"`，从 ko 里删掉，别混进韩文句。
5. 「说明1/2/3」→ `senses[]`；带表格的说明 → `tables[]`（`headers` 表头、`rows` 每行单元格）。
6. **概念/分类条目**（如"陈述句间接引用""时制词尾"）：书上标题是中文，`title` 直接用中文，韩文形式放 `pattern`/`tables`。
7. 练习题页（Test / 选择题）**跳过**，不是语法条目。

### ③b 概念/词类单元的约定（Unit 1-4 实践总结）

Unit 1-4（体词 / 谓词 / 修饰词独立词 / 句子·终结词尾）是**词类/句法概念**章节，不是「助词/词尾 + 例句」的离散点，排版更复杂。以下约定按书本 1:1 还原、并已用户验收：

1. **书本阅读顺序 = `tables[]` 数组顺序**。因为详情弹窗固定按 说明 → tables → 例文(条目级) → 注意 渲染，跨"说明1/说明2"交替的内容**全部塞进 `tables[]`**（用 `level`/`text`/`examples`/`note` 承载），才能保住书里的先后顺序。
2. **两级说明标题**：书里的「说明1/说明2」→ `level:'section'`（大节，`text` 放定义正文）；「① ② ③」小项 → `level:'item'`。前缀不要重复写（不写"说明1 · ①"，① 项直接叫"① 数数"，由上方 section 统领）。
3. **说明拆条，别挤一段**：一段话里并列的多类定义（如"自动词…他动词…"、四类名词）→ 拆成 `senses[]` 多义项，或拆成"定义表"（`headers:['类型','说明']`），或每个 `item` 的 `text`。禁止把多类塞进 `explanation` 一大段。
4. **例词（词/义 短表达）** → 用某个 table 的 `examples`（内联紧凑：`옷 두 벌 / 两套衣服`）。**例文（整句）** → 单句可放条目级 `examples`（白卡片+"例文"标签），跨说明交替的多组例文放 table 的 `examples` 并起标题"例文"。
5. **书里"表内例词列"抽出来**：`类别/单位/例词` 那种表，把"例词"列删掉、只留 `类别/单位` 网格，例词移到该 table 的 `examples` 平铺（更清晰、不塞爆单元格）。
6. **长词表用 2 列，禁止 4 列**：韩/中词表（数词、量词、副词、点/小时/月/日…）一律 `['韩语','中文']` **2 列竖排**，不要用"重复列对"的 4 列表（会横向滚动）。真·多列表（人称代词 人称/类别/单数/复数、词干×时态、时态×词性）才保留 3-4 列。
7. **合并单元格**：书里纵向合并的表头/类别（人称代词的"第一人称"跨 2 行、终结词尾"-에요"跨 2 行）→ 用 `merges`，合并格会跨行**真正垂直居中**。
8. **注意就近**：某张表专属的"注意"用该 table 的 `note`（渲染成表下橙框、按 ①②③ 分条）；整条通用的注意才用条目级 `note`。

### ③c 每单元封面页（Unit N 标题页）不建条目，只是 OCR 里的分隔。

## ④ 接入：写进 `constants/grammarBook.ts`

- 顶部定义书名常量：`const BOOK2 = '书名';`（多本书就多个常量）。
- 把 ③ 的对象追加进 `GRAMMAR_BOOK` 数组，每条带上 `book: BOOK2` 和 `unit`。
- `GRAMMAR_BOOKS`（按 book 归类）会自动生成，无需手动改。
- **不用改 UI**：分组列表、详情弹窗、高亮、表格、句型分条、搜索都是通用的，新书数据进来即生效。

> 多本书的 UI「选书切换」目前未做（只有一本时不需要）。真加了第二本再补一个顶部切换控件即可，数据结构已按 `book` 归好类。

## 展示约定（已内置，结构化时对齐即可）

| 现象 | 规则 |
|---|---|
| 例句语法高亮 | 详情弹窗里自动从 `title` 提取韩文形式高亮成紫色；助词/词尾/`이다`变形/词尾并入前字都已处理；元音缩约(가+아서→가서)等无法自动，属固有限制 |
| 句型分条 | `pattern` 里用 `；` 或「空格/空格」分隔的多句会自动拆成带 `·` 的多行；`-ㄴ/은`、`动词词干/形容词词干` 内部的 `/` 不拆 |
| 表格 | 列少能放下→撑满屏宽；列多→固定列宽 + 横向滚动。标题左对齐、黑体加粗，`level` 决定字号层级 |
| 表格标题下 | 顺序渲染：`text`(普通说明段落) → 网格 → `note`(橙色注意框，按①②③分条) → `examples`(内联例句) |
| 合并单元格 | `merges` 的格按列渲染、`span×行高` 跨行**垂直居中**；非合并表走行渲染 + 斑马纹 |
| 例句样式 | 条目级 `examples` = 白卡片（韩文大、译文小、AI补译标"AI译"）；表内 `examples` = 无底内联（韩文+译文同行、细分隔线） |
| 注意分条 | 所有 `note.text` / 表 `note` 里的 ①②③… 自动拆成独立行 |
| 卡片描述 | `explanation` 为空时自动兜底取首个带 `text` 的 table |
| 分组标题过长 | 自动截断省略，`X 条` 和箭头保持可见 |
| 收藏 | 每条卡片右上 ⭐ → 存进「我收藏的」（完整 `GrammarEntry`） |
| 搜索 | 「语法书」「我收藏的」两个标签都按 韩文/中文 关键词过滤 |
